fhir-examples🔗

Worked examples for the fhir family of Racket packages, and raco spec-bench, a benchmark for writing FHIR profiles from prose with a model. Each example directory has a README with its results.

1 Quick start🔗

Install the whole family (the packages are not on the Racket package server yet; clone the repositories side by side):

raco pkg install --link --auto fhir/fhir fhir/fhir-spec fhirpath vcl fhir/fhir-tx fhir/fhir-validation cql fml fsh fhir/fhir-server sql-on-fhir fhir-examples

Then run an example:

racket screening/main.rkt

  

seven languages, one program

raco fhir-server serve screening/app.rkt 8080

  

the same composition served

racket examples/pipeline.rkt

  

operations applied as procedures, no server

raco fsh check examples/intake-maps

  

structures, a map and an example, checked as one project

racket notes-to-fhir/main.rkt –replay notes-to-fhir/results/2026-11-03T2336-brief

  

recorded model runs, no model needed

racket ig-servers/main.rkt -v hl7.fhir.uv.ipa

  

one IG's generated server checked against the IG

raco test -p fhir-examples

  

the recorded results as floors

2 The examples🔗

  • screening/: one program, seven languages. A blood pressure screening in FHIR Shorthand, FHIR R6 resources, the FHIR Mapping Language, VCL, CQL, SQL on FHIR, and a capability app that serves the composition. Each file is a module checked as the program compiles; the modules’ values are FHIR resources and procedures over them, joined by FHIR operations. The seams are checked too: the map against the structures FSH defined, each mapped reading against the profile, the module registry doubling as the canonical registry.
    (require (only-in "profile.fsh" [compiled clinic])
             (only-in "intake.fml" [transform intake->reading])
             (only-in "bp-panels.vcl" [valueset bp-panels])
             (only-in "screening.cql" [evaluate screen])
             (only-in "readings.sof" [->json view-definitions]))
    (~> form intake->reading (ensure-valid #:profile profile))   ; FML, then the FSH profile
    ($expand #:valueSet bp-panels)                               ; the VCL value set, expanded
    (screen patient-data #:parameters (hash "Panel Codes" codes)) ; CQL over one patient
    (view-rows view)                                             ; SQL on FHIR over the same data

  • examples/pipeline.rkt: operations as procedures. A QuestionnaireResponse becomes a Patient through $transform, is validated, and its gender is checked with ValueSet/$validate-code. No server.

  • examples/intake-maps/: structures and the map between them as one project. A logical model (an intake form) and a profile (a screening Observation) in FSH, the map from one to the other in FML, and an example form. raco fsh check compiles the structures, checks the map against them and transforms the example into a valid Observation; –pack writes one package holding all three; (structure-map url) then applies the map by canonical from that package. The fml document walks through it.

  • notes-to-fhir/: free text to conforming FHIR, with a model. Clinic notes become FHIR, held to a small IG written in FSH by $validate, each issue fed back by resource and path until the data conforms; then the screening rule runs over it. --brief leaves the FSH out of the prompt; --replay re-checks a recorded run without a model.

  • ig-servers/: servers generated from six published IGs (IPA, AU Core, Plan-Net, Drug Formulary, CARIN Blue Button, SDC), checked against nothing but each IG: every example accepted, read back, found by every advertised search parameter and include; every example made invalid refused; every requirement of the CapabilityStatement met. Packages are fetched into ig-servers/packages/ and locked.

3 The benchmark🔗

 (require fhir-examples/bench) package: fhir-examples

A task is a published IG’s FSH minus one leaf profile and its instances. The prompt gives what the IG publishes about the profile (description, purpose, and the short, definition and comment text of every element it constrains) and names the constrained elements, never a constraint value. The answer is FSH. The score is against the profile HL7 published.

procedure

(list-tasks ig)

 → (listof (list/c string? string? exact-nonnegative-integer?))
  ig : path-string?
The profiles that can be taken out alone (no other local profile derives from them): name, id, number of examples.

procedure

(make-task! ig published profile out) → path?

  ig : path-string?
  published : path-string?
  profile : string?
  out : path-string?
Writes out/project/ (the IG without the profile and its instances), out/prompt.md and out/task.rktd. published is the IG’s package.

procedure

(score-task task candidate) → hash?

  task : path-string?
  candidate : string?
Compiles the candidate FSH inside the task’s project with fsh/check, then scores it: 'check_errors; 'fidelity, facets agreed with the published differential (min, max, mustSupport, types, binding, fixed and pattern values, slicing) as (list ok total), and 'extra_constrained_elements; 'accepts_published_examples, the IG’s examples validated against the candidate’s profile; 'examples_conform_to_published, the candidate’s examples validated against the published profile; 'rejections and 'diagnostics_text.

procedure

(run-task! task    
  command    
  [#:rounds rounds    
  #:timeout timeout]) → (listof hash?)
  task : path-string?
  command : string?
  rounds : exact-positive-integer? = 3
  timeout : (and/c real? positive?) = 1200
Runs a shell command on the task: the prompt on its stdin, the answer on its stdout (the last “‘fsh block is the candidate), through files, its process group killed past the timeout. Each round’s prompt, answer, FSH and score go under runs/<stamp>/ and a line is appended to results.jsonl. After a round with check errors the next prompt carries the answer and the diagnostics; rounds stop when the answer checks clean.

procedure

(published-package name) → path?

  name : string?
A package by path, by file name in fhir-spec, or by name ("hl7.fhir.us.mcode-4.0.0").

raco spec-bench🔗

raco spec-bench list <ig-dir>

raco spec-bench make <ig-dir> <published-package> <Profile> <task-dir>

raco spec-bench score <task-dir> (--oracle | --empty | <candidate.fsh>)

raco spec-bench run <task-dir> --model '<shell command>' [--rounds n] [--timeout seconds]

End to end, on mCODE (its FSH sources are vendored in the fsh repository):

raco spec-bench list ../fsh/tests/vendor/mcode-4.0.0

raco spec-bench make ../fsh/tests/vendor/mcode-4.0.0 hl7.fhir.us.mcode-4.0.0 TumorSize task/

raco spec-bench score task/ --oracle

    the IG's own FSH: the ceiling this compiler allows

raco spec-bench score task/ --empty                  nothing: 0

raco spec-bench run task/ --model 'claude -p' --rounds 3 --timeout 1200

cat task/results.jsonl

The model command reads the prompt on stdin and answers on stdout; the last “‘fsh block is the candidate. Each round’s files are under task/runs/<stamp>/.
