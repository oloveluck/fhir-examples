# Round 2 and the test split, 2026-11-15

What changed since the baseline (same day), then both benchmarks again with Claude Sonnet 5.5, and
FHIR-AgentBench once on a held-out test-split sample. Code: fhir e2fb748, fsh 53d110e,
fhir-examples 479f1d7. Full tables and every miss: `2026-11-15-round2-full.md`,
`2026-11-15-test-split-full.md`.

**What changed**
- The tools (fhir CLAUDE.md, "Fewer calls, fewer tokens"), from the 30 baseline questions both arms
  missed and the calls agents made: FHIR chained search (`medication.identifier=Heparin`),
  `_profile` on every type, a census that names a type's kinds and what points at it, search rows
  that name referenced resources, split a Quantity into number and unit and say shared cells once,
  `describe Patient/x as=summary asof=…` (which stays were open then), FSH pages with one Alias
  block, and `raco fhir guide data`, a one-page card.
- The harness (harness 2, for every arm): the same built-in tools (Bash, Read, Write), one closing
  line, and the workspace arms get the card in their prompt where the REST arms get their curl
  lines. A new arm, **mcp**: the same verbs as MCP tools.

**What it shows**
- On questions it was never tuned on, the workspace answers 118/150 against curl's 110, with
  retrieval precision 0.88 against 0.77 and recall 0.81 against 0.74, in 16% fewer turns, 15% fewer
  input tokens and 17% less cost. On the valid split, over two runs, it averages 114.5 against 110.
- Most of the drop from the baseline (342k -> 58k input tokens a question) is the harness:
  Claude Code's default tool set is most of every turn's context. The rest arm fell too (279k ->
  82k). What is the workspace's own: it now uses fewer tokens and turns than curl, where it used 22%
  more, because the reading card replaced the guide agents read first (no round-2 agent read it),
  and answers say more per call (agents asked for FSH ~40 times a run, the as-of summary ~20,
  `_profile` 20–31, chained searches 13–15).
- The MCP arm scores as the shell arm does but costs more: its tool definitions and JSON-RPC answers
  are in every turn's context (85–90k tokens against 58–59k).
- MedAgentBench is at its ceiling for every arm (293–296 of 300). The task7 misses (`94 mg/dL`
  where the grader wants `94`) are gone with value and unit as two columns; the three tasks every
  arm misses are still the grader's `route` string, which FHIR R4 does not allow. Curl on our server
  is the cheapest arm there: its tasks are a lookup or an order, which a REST call answers in one.

**Caveats**
- The FHIR-AgentBench judge is an LLM: identical answers are sometimes scored differently (an
  answer "MRSA SCREEN" against a true "MRSA SCREEN" was marked wrong once); differences of 3–5
  questions are within run-to-run and judge noise. The test split was run once per arm.
- Cost depends on prompt caching: MedAgentBench's second workspace run cost $4.94 against $12.19
  for the first, with the same tokens, because the first had filled the cache. Compare tokens.
- FSH as the writing format went unused: offered for MedAgentBench's POSTs, 0 of 309 workspace
  payloads and 5 of 122 MCP payloads were FSH. Its examples are JSON, and agents follow them.
