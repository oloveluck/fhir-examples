# Baseline, 2026-11-15

Both benchmarks in full with Claude Sonnet 5.5 (`--model sonnet`), each item a fresh `claude -p` agent
in an empty directory; graded by the benchmarks' own graders (MedAgentBench's `refsol.py` against its
HAPI server; FHIR-AgentBench's `evaluation_metrics.py` with Sonnet 5.5 as its judge). Agent cost
$161.88 in all (the judge's not counted). Code: fhir 7e4e91b, fhirpath 227825e, fsh 686eb54,
cql 3072977, sql-on-fhir 689f5f6, fhir-examples 0fa3a26.

**What it shows**
- Our server is a drop-in for the benchmark's HAPI server: curl agents score 98.3% on it and 99.0% on
  HAPI; it answers the 784 searches the grader makes over the 98 patients with exactly HAPI's resources.
  Under the benchmark's own one-action-per-turn protocol it scores 75.3% against HAPI's 70.7%: HAPI
  pages at 20 and its first page has no `total`, so the model spends its turns paging (task9: 2/30
  against 20/30).
- FHIR-AgentBench: the workspace verbs answer 117/150 (78.0%) against 113/150 (75.3%) for curl on a
  plain FHIR server over the same store, with higher retrieval precision (0.88 against 0.81) and
  recall (0.77 against 0.74), for ~22% more tokens and time.
- MedAgentBench's tasks are lookups and orders a curl agent already does at 98–99%; the workspace arm
  is 97.0%. Its 5 task7 misses are the answer's form: the workspace's rows show `94 mg/dL`, the
  agents answered that, the grader wants `[94]`.

**Caveats**
- One run per arm: a difference of 2–4 questions is within what reruns move.
- 16 FHIR-AgentBench agents wrote their answer to a mistyped directory (one `/` written as `-`); the
  answers were recovered and the runs scored again (`fab/run --collect`); the prompt now names the
  file's absolute path.
- MedAgentBench's grader holds a medication order's `route` to the string `"IV"`/`"oral"`; FHIR R4's
  `Dosage.route` is a CodeableConcept, so an agent that writes valid FHIR is marked wrong (task5_21,
  task5_25, task9_3 are missed by every agent arm). task2 (an age) is 0/30 under the official protocol
  on both servers: the model has no clock or calculator there.
- The official protocol against our server was cut at 201/300 by an argument-length limit in the
  first (Python) harness; the other 99 ran with the Racket harness (prompts on stdin).
